# 签约主体一致性识别

## 1. 目标
识别应届生就业签约文件中与“签约主体一致性识别”相关的风险线索，输出可追溯、可解释的 `RiskFinding`。本 Skill 不对未提供的事实作推定。

## 2. 适用范围与关键词
**适用关键词：** 甲方、乙方、用人单位、实际用工单位、派遣、关联公司

**重点风险模式：**
协议主体、盖章主体、发薪主体、招聘主体或实际工作主体名称不一致；主体名称、统一社会信用代码、地址等信息缺失；出现关联公司代签线索。

## 3. 识别流程
1. 从 `clauses[]` 中筛选相关条款，并保留原始 `clause_id`、页码和章节路径。
2. 执行硬规则检测：关键词、金额、日期、期限、空白字段、主体名称及跨条款一致性（适用时）。
3. 仅当条款含义依赖上下文、存在模糊措辞或权利义务关系不明确时，执行语义分析。
4. 将命中结果与同一文件其他相关条款交叉核对，避免断章取义。
5. 输出 `RiskFinding`；不能确认的事项标记为“待核实”，并列明缺失信息。

## 4. 规则集
R09-01 签约与盖章主体不一致；R09-02 招聘与签约主体不一致；R09-03 发薪或用工主体不一致；R09-04 主体身份信息缺失；R09-05 关联公司关系待核实。

## 5. 本 Skill 的判断方法
抽取各页面和签章处主体名称；跨文件、跨条款比对；对简称、品牌名与法人名称差异标记待核实，不直接认定违规。

## 6. 风险等级建议
- **高：** 原文直接显示重大经济责任、关键权益放弃或明显不对等安排，且证据充分。
- **中：** 条款关键内容不明确、范围过宽或存在较大争议可能，需要签约前确认。
- **低：** 信息披露或程序性问题，当前材料显示影响有限。
- **待核实：** 缺少合同附件、主体信息、历史事实或知识库依据，不能可靠定性。

风险等级必须结合原文证据确定；不得仅因命中关键词自动判为高风险。

## 7. 输出要求
每个命中项均按 `00_统一规范与接口契约.md` 中的 `RiskFinding` 输出。该 Skill 的 `skill_id` 固定为 `OG-RISK-09`，`risk_type` 使用“签约主体一致性识别”。

- `evidence`：逐字引用原文，禁止改写或拼接成合同中不存在的句子。
- `triggered_rule`：填写本 Skill 对应规则编号。
- `explanation`：说明原文事实、风险推断及二者区别。
- `suggestion`：要求对方书面说明各主体关系、劳动合同签署方、工资发放方及社保缴纳方；核对企业登记信息和授权文件。
- `student_tip`：一定要弄清楚到底和哪家公司签约，谁给你发工资、缴社保，不能只看招聘时使用的品牌名称。
- `knowledge_evidence`：当前留空 `[]`；接入知识库后仅填写真实检索结果。
- `confidence`：0 到 1；证据不足时降低置信度。
- `status`：已确认 / 待核实 / 未命中。

## 8. 知识库依赖（预留）
**待知识库模块接入，当前不填写法律依据。**

- 检索主题：甲方、乙方、用人单位、实际用工单位、派遣、关联公司
- 建议检索字段：法规/政策名称、条款编号、效力状态、适用地区、发布日期、生效日期、原文片段、来源链接或文档 ID。
- 检索约束：优先适用现行有效且与文件类型、签约时间、适用地区相匹配的依据；无法确认时返回空结果并提示人工核验。

## 9. 误报控制
- 不以单个关键词直接判定违法或无效。
- 不把合同未写明的信息自动视为事实不存在。
- 不把学生尚未提供的附件内容当作合同约定。
- 对简称、别名、模板字段和格式噪声进行上下文确认。
- 若原文不足以支撑风险结论，输出“待核实”或不输出风险项。
