# OfferGuard 风险识别 Skills

## 统一执行原则
- 本 Skill 仅审查应届生就业签约文件，包括三方就业协议、劳动合同及与入职、培训、保密、竞业限制相关的附件。
- 只依据输入文件中可定位的原文作判断；不得根据常识补写合同内容。
- 优先执行确定性硬规则；只有存在语义歧义或需要结合上下文判断时，才进入语义分析。
- 不得把“未发现”表述为“绝对不存在风险”。缺少必要页面、附件或上下文时，应标记为“待核实”。
- 不得自行编造法律条文、政策名称、司法案例、文号或检索结果。
- 知识库内容尚未接入时，`knowledge_evidence` 留空，并明确提示“待知识库核验”；不得生成虚假的法律依据。
- 识别结果是签约风险提示，不代替律师意见或劳动监察、仲裁机构的正式认定。

## 输入约定
输入为解析后的合同文档及元数据，至少尽可能包含：
- `document_id`：文件唯一标识
- `document_type`：三方协议 / 劳动合同 / 劳务协议 / 附件 / 未知
- `clauses[]`：条款数组，每项包含 `clause_id`、`clause_type`、`text`、`page`、`section_path`、`file_type`
- `parties[]`：如解析器已识别，包含主体名称及角色
- `document_text`：全文文本（可选，用于跨条款比对）

## 统一输出：RiskFinding
每个风险点输出一个对象：
```json
{
  "risk_id": "唯一风险编号",
  "skill_id": "对应Skill编号",
  "risk_type": "风险类型",
  "risk_level": "高 / 中 / 低 / 待核实",
  "title": "简短风险标题",
  "evidence": [
    {
      "clause_id": "原条款编号",
      "original_text": "合同原文，不得改写",
      "page": 1,
      "section_path": "章节路径"
    }
  ],
  "triggered_rule": "命中的规则编号及规则描述",
  "explanation": "说明风险如何产生，区分事实与推断",
  "suggestion": "可执行的核实或修改建议",
  "student_tip": "面向学生的通俗提示",
  "knowledge_evidence": [],
  "confidence": 0.0,
  "status": "已确认 / 待核实 / 未命中",
  "missing_information": []
}
```

## 风险等级参考
- 高：原文直接呈现明显重大风险，可能造成较大经济损失、重要权利放弃或责任显著失衡。
- 中：存在不清晰、不对等或可能引发争议的约定，需要签约前确认或修改。
- 低：提示性、程序性或影响相对有限的问题，仍建议留意。
- 待核实：现有材料不足以判断，必须补充附件、事实或知识库依据。

## 输出约束
- `evidence` 必须逐字引用输入原文，并尽可能附条款编号、页码和章节路径。
- `triggered_rule` 应写清规则编号；语义判断须同时列出支持判断的上下文。
- `knowledge_evidence` 仅允许填写真实检索返回的知识库记录；当前为空时使用 `[]`。
- 没有命中风险时可输出空数组；不要为了凑数制造风险。
- 同一条款触发多个 Skills 时允许分别输出，但应通过 `risk_type` 和证据避免重复描述。
