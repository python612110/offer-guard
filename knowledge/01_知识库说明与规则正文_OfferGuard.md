# OfferGuard 就业签约文件风险审查知识库：说明与规则正文

## 使用说明

**项目**：应届生三方就业协议、劳动合同及入职、培训、保密、竞业限制相关附件的商业初审知识库
**适用范围**：我方为签约学生/劳动者；审查三方就业协议、劳动合同、劳务/服务/合作协议及相关附件。用人单位视角的合规对照暂不适用。
**先看哪里**：先看「接受边界」的法定阈值，再看「规则总表」与「判断细则」；确定后记录确认人和日期。待确认参数须人工复核，不得直接定性。
**来源层级**：LC=《劳动合同法》；SI=《社会保险法》；AG=三方就业协议书样本模板；NP=2026年高校毕业生等青年就业工作通知；SK=OfferGuard 风险识别 Skill 规范。法规条文为强制依据；样本模板仅作字段与结构参考，不支持自拟百分比。
**输出状态**：风险等级分高 / 中 / 低 / 待核实；命中状态分已确认 / 待核实 / 未命中。单条命中不等于整份文件无风险，单条未命中也不排除其他条款风险。
**材料缺失**：附件、页面或上下文未提供时标记「待核实」并列明缺失信息；仅在全文及相关附件齐备时，才能判断「未见相关保护」。
**事实保护**：缺失记为 null；计划日期不是实际事件；合同名称不决定法律关系；商业使用、报到或付款不当然构成验收或同意。
**参数及例外**：法定阈值来自现行法律条文；地方最低工资、社保费率、特殊工时审批口径等须按签约地规定另行核验，不在本库自拟数值。
**规则规模**：12 个风险识别 Skill（OG-01～OG-12），共 63 条子规则；25 项法定/审查边界参数（B01～B25）；字段字典覆盖输入接口、主体信息与各条款提取字段。
**测试设计**：待接入 Agent 运行；实际识别结果留空，不在本库预置测试结论。
**接口契约**：输出统一为 RiskFinding 对象（字段见「字段字典」）；evidence 必须逐字引用原文，knowledge_evidence 仅填写真实检索返回的知识库记录。
**自动化范围**：本库为声明式知识，非可执行引擎；仍需字段抽取、规则路由、语义判断与证据校验配合。
**专项事项**：不提供主体真实性核验、实时名单筛查、最终法律效力或仲裁/监察结论；法律争议、地方政策分流给法务、人社部门核查。
**误报控制**：不以单个关键词直接判定违法或无效；不把合同未写明的信息视为事实不存在；简称、别名、模板字段和格式噪声须结合上下文确认。
**政策背景**：NP 通知明确依法打击虚假招聘、「培训贷」「招转培」、滥用试用期等违法行为，纠正无故解约、就业歧视，作为风险提示的政策导向，不直接作为个案定性依据。
**文件同步**：Excel 与后续 JSON 为同版快照；修改 Excel 不会自动同步 JSON，维护人须同步校验后再发布。

## 规则正文

各规则按 OG 编号合并规则总表、判断细则、建议写法及该规则的来源映射；子规则判断条件、例外与误判保护一并列出，并非仅摘录风险摘要。

### OG-01 违约金风险识别

**条款分类**：违约责任与赔偿（C01）
**Skill 编号**：OG-RISK-01
**适用条件**：所有含违约/赔偿约定的协议与合同
**关键词**：违约金、违约责任、赔偿、解约责任
**提取字段**：penalty_amount、penalty_trigger、penalty_payer、penalty_basis、penalty_cap
**建议风险检查**：高额违约金；触发条件宽泛；仅约束学生不约束单位；将一般离职、拒绝录用、未报到一概约定高额赔偿；金额/计算方式/支付对象不清。除服务期、竞业限制外约定劳动者违约金为高风险待核验。
**依据条款**：劳动合同法 §22、§23、§25、§26、§90
**适用立场**：我方为学生/劳动者

| R01-05 | 违约金约定能对应到法定可约定情形并有真实培训/保密事实支撑。 | 在法定两类情形之外约定劳动者违约金。 | 是否属于专项培训或保密岗位事实不清，需结合上下文核验。 | 不以单个关键词判违法；法律适用与效力由法务/仲裁确认。 | 岗位性质、培训事实等关键事实缺失→待核实。 | 劳动合同法 §22、§23、§25、§26 |

**建议写法主题**：违约金风险识别
**建议中文写法**：仅在专项培训服务期、竞业限制两类情形下约定劳动者违约金，并写明触发情形、计算基数、上限与支付对象；双方违约责任对等。
**核实/修改建议**：确认违约金适用的具体情形、计算依据、责任上限及法定例外；要求对方书面说明，并修改模糊、过宽表述；超出两类情形的违约金条款要求删除。
**学生通俗提示**：签约前不要只看违约金数字，还要看什么情况下要付、怎么算、谁承担。
**依据条款**：劳动合同法 §22、§23、§25、§26、§90

**条款分类**：劳动报酬（C10）

## JSON结构与维护

parameters 对应接受边界；rules 按规则 ID 汇总规则总表、判断细则、建议写法及来源映射；fields 对应字段字典；source_mappings 保留完整来源映射。JSON 为声明式知识，开发方仍需实现字段抽取、规则路由、语义判断及证据校验。

风险等级分高 / 中 / 低 / 待核实，命中状态分已确认 / 待核实 / 未命中；规则条件、例外与信息不足处理须一并读取，材料不足不能自动当作符合。evidence 须逐字引用原文，knowledge_evidence 仅填写真实检索返回的法规/政策记录，未接入时留空 []。
